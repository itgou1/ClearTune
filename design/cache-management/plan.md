日期：2026-10-30。状态：缓存、公共下载、历史迁移和播放优先级已实现；调试构建、181 项单元测试、30 项设备测试和 Android Lint 已通过。旧系统与厂商真机的验证边界见[验证记录](../../release-notes/validation-cache-download-2026-10-30.md)。

将「我的 → 设置」中的播放缓存容量选择和清理操作整合为独立的「缓存管理」页面。扩大容量范围，以带固定档位的滑动条作为主要操作方式，增加保存步骤，并分别管理播放缓存和图片与临时缓存。取消应用内私有离线保存模式，主动下载统一保存到设备公共音乐目录，并以「本机下载文件 → 播放缓存 → 服务器在线音频」作为播放优先级。

## 功能边界

| 类型 | 用途 | 存储与生命周期 |
| --- | --- | --- |
| 播放缓存 | 播放时自动保存数据，减少重复加载 | 应用管理，受容量上限和自动淘汰控制，可手动清理 |
| 下载音乐 | 用户主动保存完整歌曲，供稳定离线播放和其他播放器使用 | 公共 `Music/ClearTune/`，用户主动管理，不受缓存清理或容量上限影响 |

不再提供「仅应用内保存」或第三种离线保存模式。动态缓存可能不完整或被淘汰，不能承诺稳定离线收听；需要完整离线播放时提示下载歌曲。后台任务临时文件仍可存放在应用内部，但不作为面向用户的长期保存模式。

## 当前问题

- 容量只有 512 MB、1 GB、2 GB、4 GB，默认 512 MB。
- 容量弹窗点击即保存并关闭，缺少预览和确认；现有缓存淘汰器在调小上限时会清理超额缓存。
- 「清理缓存」处理临时缓存，不包含单独存放的播放缓存，名称容易产生误解。
- 已用容量缺少整体展示，当前字节格式化没有 GB 分支。
- 当前下载写入按账号隔离的内部 `offline_music` 目录，以任务 ID 命名，普通文件管理器不可见。
- 退出登录保留私有下载，下载列表仅展示当前账号，其他历史账号的文件缺少统一管理入口，可能长期占用空间。

## 页面结构

设置页的「下载与缓存」分组保留「仅 Wi-Fi 下载」，将播放缓存和清理缓存两行合并为「缓存管理」入口，摘要显示可管理缓存的合计占用。进入页面后按以下顺序展示：

1. 空间概览：播放缓存已用容量、当前生效上限、使用进度和设备可用空间。
2. 容量设置：待保存容量、固定档位滑动条、自定义入口、策略说明和保存按钮。
3. 分类清理：播放缓存、图片与临时缓存各自的占用和清理按钮。
4. 下载说明：「已下载歌曲不受缓存清理影响」，提供下载管理入口；存在旧版私有下载时显示迁移提示和占用大小。

「我的」中的下载入口统一使用「下载管理」，已完成文件以本机下载索引展示，切换账号后仍可管理。在线音乐库和下载任务的服务器身份继续按账号隔离；已完成的公共文件与当前登录状态分离。

## 容量和滑动条交互

| 项目 | 计划行为 |
| --- | --- |
| 固定档位 | 512 MB、1 GB、2 GB、4 GB、8 GB、16 GB、32 GB |
| 刻度位置 | 七档等距排列，使用档位索引映射容量，不按字节数比例分布 |
| 拖动 | 自动吸附最近档位，顶部实时显示待保存容量 |
| 点击 | 点击轨道或刻度直接选中相应档位 |
| 生效时机 | 拖动、点击和松手均只更新草稿；点击「保存设置」后写入配置 |
| 自定义 | 数字输入配 MB／GB 单位选择，首版支持 512 MB 至 32 GB；MB 为整数，GB 支持可精确换算为整数 MB 的数值 |
| 自定义回显 | 顶部标明「自定义」和精确值；滑条不把非预设值伪装成某个固定档位，首次拖动后切换回档位模式 |
| 默认和迁移 | 保持默认 512 MB，保留已有 512 MB、1 GB、2 GB、4 GB 用户配置，不自动扩大占用 |

自定义与滑动条使用同一份草稿。空值、负数、格式错误、超范围数值需就地提示，不能静默改成默认值。内部延续整数 MB 存储，容量换算统一采用 1024，并用 Long 计算字节数。

窄屏和大字体下保留所有刻度点，仅显示能容纳的关键刻度标签；当前容量始终完整显示。支持屏幕阅读器播报当前容量及逐档增减，交互触控区域至少 48dp，选中状态不能只靠颜色表达。

## 保存和离开流程

1. 页面读取已保存容量，并建立独立草稿；旋转屏幕保留草稿，统计刷新不能覆盖正在编辑的值。
2. 未修改时保存按钮禁用；修改后显示「未保存」，空间概览继续展示已生效的上限。
3. 保存时重新读取使用量。新上限低于实际占用时，提示「保存后将自动清理部分播放缓存，可能影响缓存歌曲的离线播放」，用户确认后执行。
4. 写入失败保留草稿并允许重试；写入成功提示「设置已保存」。清理仍在进行时单独显示状态，不能将配置已保存等同于清理已完成。
5. 离开时如有草稿，提供「保存并离开」「放弃修改」「继续编辑」。保存并离开复用同一保存及超额清理确认流程。

设备可用空间为提示信息，不把上限理解为立即分配空间；不因剩余空间小于上限就禁止保存。运行时增加低空间保护，建议初始阈值为 1 GB，最终依据缓存写入路径验证：触及阈值时停止新增缓存写入，保留在线播放和读取已有缓存的能力，空间恢复后允许继续写入。该保护必须与扩大容量一起验证。

## 分类清理流程

| 类别 | 范围 | 清理前说明 |
| --- | --- | --- |
| 播放缓存 | 在线播放产生的音频缓存 | 清理后再次收听可能需要联网，部分歌曲将无法依赖缓存离线播放；已下载歌曲保留 |
| 图片与临时缓存 | 可重新生成的界面图片缓存及确认可安全删除的临时文件 | 图片可能需要重新加载，下载歌曲及离线封面保留 |

每类使用独立的清理按钮和确认弹窗，列明类别、预计可清理大小及影响。第一版无需再增加「全部清理」，避免重复入口。

- 扫描中显示「正在计算」，不能用 0 B 代替未知值；为 0 时禁用清理。
- 执行中显示进度状态并禁止重复提交，容量保存与清理任务串行协调。
- 完成后重新统计，显示「已释放 X MB／GB」；以缓存组件实际移除数据或可靠前后统计为依据，不能把设备总剩余空间变化直接当作清理结果。
- 部分失败明确提示并保留实际剩余量，允许重试；播放过程中产生的新缓存不应被误报为失败。
- 正在播放的资源优先保留，本次清理显示跳过情况和剩余大小，避免清理导致当前播放中断。后续用户可再次清理，不默认延迟删除。
- 页面进入、回到前台、保存和清理结束后刷新；页面可见且播放写入时节流刷新占用，后台不持续遍历目录。

## 下载到设备

新下载统一保存到公共 `Music/ClearTune/`，不提供应用内部长期保存选项。文件名使用「歌手 - 歌名.扩展名」，清理非法字符，对重名添加稳定后缀，不能覆盖无关文件。保留下载音频的原始格式和已有内嵌元数据，不仅通过改扩展名转换格式。

- Android 10 及以上通过 MediaStore 管理公共音频，下载过程中使用未发布状态，写入完成并验证后才对外发布；Android 8、9 按项目最低支持版本提供公共目录权限与媒体扫描兼容路径。权限不足时明确提示，不静默退回私有下载。
- 数据层保存可访问的 URI、文件名、大小、格式、来源服务器、来源账号、歌曲标识及可用的版本信息，不假定公共 URI 可以转换为文件路径。
- 建立设备级已完成下载索引，下载任务继续保留账号和会话边界。切换或退出账号取消、暂停相应任务，不删除已经完成的公共文件；登录页或未登录状态提供本机下载管理入口。
- 下载管理显示保存位置、占用和可用状态，支持播放、分享、定位文件或通过系统界面打开。不同系统无法定位具体文件时显示目录信息并提供系统文件访问入口。
- 保留暂停、继续、取消、失败重试、批量下载和仅 Wi-Fi 下载能力；处理断点续传、空间不足、进程终止和发布失败，不遗留对外可见的损坏文件。
- 删除操作区分「移除记录」与「删除设备文件」并说明后果；取消删除或系统授权失败不能先删除记录。仅移除记录会同时取消自动播放关联，但保留文件本身。
- 用户通过文件管理器移动、删除文件或撤销访问权限时，刷新为不可用，允许重新定位或下载；不显示虚假的已完成可播放状态。
- 公共下载不随退出账号或缓存清理删除。卸载后重新安装时，本机索引可能丢失，需通过系统授权重新关联文件，不能承诺自动恢复来源身份。

第一版使用固定公共目录；自选目录、任意本地音乐库扫描留待后续。下载封面优先使用音频原有内嵌封面；需要保存的独立封面作为下载关联资源管理，普通缓存清理不删除仍被下载文件使用的资源，最后一个引用删除后才回收。

## 历史私有下载迁移

提供「旧版下载处理」入口，扫描所有历史账号的私有下载和残留，不要求重新登录原账号，也不自动删除已有文件。汇总展示来源账号或可识别的本机标识、大小及处理状态。

1. 完整文件可单首或批量「导出到设备」，也可明确选择删除；未完成下载和孤立残留单独列出，不冒充完整歌曲导出。
2. 优先读取原账号数据库中的歌曲名称和来源身份。缺少元数据时使用安全的回退名称，标记来源未知，不按歌名自动关联在线歌曲。
3. 迁移复制已有音频，无需重新下载；发布公共文件前验证完整性，至少核对长度和内容校验值。
4. 导出、校验、公共文件发布和索引保存全部成功后，才删除旧音频并更新原账号下载记录；封面按引用迁移或回收。任何失败保留可恢复的原文件。
5. 迁移状态持久化，允许中断后继续，避免重复导出；部分成功时逐项显示结果。清理旧文件失败时保留清理状态，后续只重试清理。
6. 迁移完成前兼容播放仍有效的旧文件，并纳入下载优先级；这仅用于历史兼容，不再新增私有长期下载。

用户可以暂不迁移，入口与占用提示持续可见，避免历史账号内容再次成为不可管理的空间。迁移任务与相关旧下载任务、播放、删除操作协调，不能同时读写或删除同一文件。

## 播放优先级与回退

对普通歌曲统一使用下列解析流程，覆盖列表播放、队列恢复、上一首、下一首及重复播放；电台继续使用现有在线直播数据源。

| 优先级 | 来源 | 使用条件与行为 |
| --- | --- | --- |
| 1 | 本机下载文件 | 关联匹配，文件存在且可读取，直接通过 URI 播放，不依赖服务器登录或联网，也不再复制进播放缓存 |
| 2 | 播放缓存 | 没有有效下载文件时读取缓存；联网时通过同一缓存数据源补齐缺失片段 |
| 3 | 服务器音频 | 缓存未命中时使用当前合法会话请求服务器，按容量和低空间策略决定是否写入缓存 |

第二、三级可以在同一次播放中按数据片段组合，不要求等缓存读取彻底失败后才联网。无网络且无完整可用来源时明确提示「本地内容不完整，请联网或下载完整歌曲」，不能无限重试。

- 自动关联以规范化服务器地址和歌曲标识为基础，并校验来源账号范围及可用版本信息；歌曲标识若不具备跨账号稳定语义，必须保留账号维度。不能仅凭歌名、歌手或文件名匹配。
- 切换账号后，设备下载列表仍可直接播放用户已保存的文件；将其用于当前账号在线歌曲的自动匹配时必须验证身份，避免跨服务器或跨账号串歌。
- 从本机下载入口播放时，不要求先获取服务器流地址；在线列表播放也应先解析本机文件，避免先请求网络才发现可离线播放。
- 文件打不开或播放中确认本地文件损坏时，更新可用状态，尝试缓存及网络回退；尽量保留播放位置和队列，限制回退次数。权限问题与文件缺失分别提示，不将普通解码或网络失败直接判为文件已删除。
- 已知服务器音频或标签版本变化时，按现有修订机制避免使用不匹配缓存。公共下载属于用户保存的文件，不自动覆盖或删除，提示更新下载；无法验证版本时不能仅凭猜测认定文件过期。

## 实现安排

### 第一步 统一容量配置与统计

- 在 `core/datastore/.../AppPreferences.kt` 扩充固定档位，将只接受预设值的校验改为整数 MB 范围校验，保留旧配置兼容行为。
- 统一容量格式化，增加 GB 显示，保留自定义值精度，不能用整数除法把 1.5 GB 显示成 1 GB。
- 定义播放缓存、临时缓存、可用空间、扫描状态、清理状态及错误信息的统一数据模型。
- 统计和清理必须使用一致的目录范围，合计不重复计算；逐一确认 `cacheDir` 内文件用途，建立可清理范围，排除仍在使用的临时文件。

### 第二步 完善缓存管理能力

- 检查 `PlaybackService.kt`、`ResizableLeastRecentlyUsedCacheEvictor.kt` 和播放数据源，将统计、清理、调整容量和低空间保护纳入统一管理。
- 使用持有中的 Media3 缓存实例提供的操作管理播放缓存，不绕过缓存索引直接删除目录，也不为同一目录同时创建多个实例。
- 明确播放服务运行与未运行时的访问方式，保证容量缩减和分类清理均可执行；正在使用的缓存资源需要与播放器协调保护。
- 复用并审查 `ArtworkCache.clearTemporary` 的图片缓存清理逻辑，通过图片库清理其受管缓存，离线封面继续排除在外。
- 文件统计及清理在 IO 线程执行；对并发任务、取消、部分失败和刷新过期结果作保护。

### 第三步 改造下载存储与历史迁移

- 改造 `DownloadWorker.kt`、`DownloadRepository.kt` 及下载数据库结构，引入公共音频写入、设备级文件索引和 URI 访问，消除对 `File(uri.path)` 的依赖。
- 将下载任务身份与已完成本机文件的管理分离，保留原有会话校验和后台调度约束。
- 实现文件发布、重名处理、外部变动识别、记录与文件分别删除，以及不同 Android 版本权限处理。
- 实现跨历史账号扫描、迁移校验、持久化进度和失败恢复，明确音频、封面及残留文件的清理范围。

### 第四步 统一播放来源选择

- 检查歌曲播放入口、`PlayerConnection.kt`、`PlaybackDataSourceFactory.kt` 及队列恢复路径，将下载文件解析放在网络地址请求之前。
- 接入设备级下载索引和 content URI 读取，统一来源身份、版本匹配、失效回退及播放位置恢复。
- 验证本机文件和完整缓存断网可播，部分缓存联网补齐，电台路径不受影响。

### 第五步 实现页面和入口

- 调整 `SettingsScreen.kt` 的入口并新增缓存管理页面及路由，沿用现有主题和组件风格。
- 扩展或拆分 `SettingsViewModel.kt` 的缓存状态，区分生效值、编辑草稿和实际缓存任务。

## 验收标准

- 七个固定档位均可点击和拖动选择，等距吸附准确；只编辑不保存不会改变配置或清理文件。
- 自定义合法值可保存并在重启后准确回显，非法值明确报错；旧配置保持不变。
- 调低至实际占用以下必须确认，并在处理后刷新占用；取消确认无副作用。
- 页面清晰区分已用容量、已生效上限、待保存容量和设备可用空间。
- 两类清理的对象、大小、确认说明和执行结果一致；部分失败不显示全部成功。
- 清理和容量调整不删除已下载歌曲及离线封面；当前播放保持稳定。
- 播放服务运行或未运行时均可完成管理，不发生缓存目录多实例冲突。
- 大容量不会产生字节溢出或容量显示截断；低空间时缓存写入可停止并恢复。
- 小屏、大字体、深浅主题及屏幕阅读器操作可用，标签和按钮不重叠、不截断关键数值。
- 新下载只生成公共目录中的完整音频文件，系统文件管理器可见，没有新增应用内长期离线保存模式。
- 切换账号及退出登录后，已完成下载仍可管理和本机播放；在线库与后台任务继续按账号隔离。
- 所有历史账号的私有下载均能被统计并导出或删除；迁移失败不丢原文件，中断后继续不重复导出。
- 删除下载记录、删除公共文件和清理缓存各自作用范围明确，系统拒绝删除时记录不会被提前移除。
- 文件被外部移动、删除或失去权限后状态可更新，重新定位或下载可以恢复。
- 本机文件有效时播放优先使用本机，无网络亦可播放；无本机文件时正确读取缓存并按需联网，断网且内容不完整时明确提示。
- 同名歌曲、不同服务器相同歌曲 ID、跨账号标识差异不会导致错误文件关联；播放入口、队列恢复和切歌采用一致的来源规则。

## 后续扩展

自动推荐容量、按歌曲选择清理缓存、按使用天数清理、超过 32 GB 的自定义上限、关闭播放缓存开关、自选下载目录及任意本地音乐库扫描暂不进入第一版。歌词等其他数据是否纳入管理，需先核实存储位置和用户编辑内容边界，再另行设计。
