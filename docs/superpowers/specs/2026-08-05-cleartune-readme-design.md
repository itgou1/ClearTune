# ClearTune README 设计

日期：2026-08-05

## 1. 目标

为 ClearTune 仓库新增根目录 `README.md`，同时服务两类读者：

- 普通用户可以快速理解项目定位、主要功能、系统要求和当前成熟度；
- 开发者可以快速了解技术栈、模块边界、构建方式和验证命令。

README 以用户体验为主，开发信息保持完整但不过度展开。所有描述必须来自仓库现有实现，不加入未经验证的下载链接、截图、徽章或未来承诺。

## 3. 首页展示内容

项目定位采用以下语义：ClearTune 是一款原生 Android 纯音乐播放器，将设备本地音乐与 WebDAV 音乐库统一管理、播放和离线使用。

核心特性聚焦已经实现的能力：

- 本地音乐扫描、分类、搜索与文件夹浏览；
- 多 WebDAV 音乐源、在线串流和后台同步；
- 断点续传、整目录下载与离线播放；
- 歌单、收藏、歌词、播放队列和状态恢复；
- 受 Apple Music 启发的简洁布局与视觉层次，但不使用 Apple 商标或专有素材；
- 支持 Android 8.0（API 26）及以上版本。

README 不设置空截图区域，不添加尚不存在的 APK 下载入口，也不将项目描述为已经正式发布。

## 4. 开发者内容

技术栈列出 Kotlin、Jetpack Compose、Material 3、Media3、Room、WorkManager、OkHttp 和 Coil。

模块架构按实际 Gradle 工程分为：

- `app`：应用入口、依赖组装和导航；
- `core`：领域模型、契约、设计系统、数据库、网络与测试支持；
- `data`：本地媒体、WebDAV 和离线下载；
- `playback`：Media3 播放服务、队列和播放状态；
- `feature`：资料库、音乐来源、下载、播放器、歌单和设置界面。

环境要求必须与构建配置一致：JDK 17、Android SDK 37、Gradle 9.5.0、最低 Android API 26。构建示例统一使用仓库内的 Gradle Wrapper，并分别给出 Windows 与 macOS/Linux 命令。

验证部分覆盖单元测试、Debug APK 和 Android 测试 APK 的构建。明确区分“测试 APK 已成功编译打包”与“已在真机或模拟器执行”，避免把未执行的设备测试写成已通过。

## 5. 安全与状态说明

WebDAV 章节说明：

- 凭据由 Android Keystore 支持的安全存储保护；
- 默认使用 HTTPS；
- 明文 HTTP 需要用户主动允许，并持续显示风险提示；
- 支持 Basic 与 Digest 鉴权。

项目状态说明主要功能已经实现，并已完成本地构建和单元测试验证；设备端自动化测试仍需在已连接的真机或模拟器上执行。

仓库当前没有许可证文件，因此 README 不声明具体开源许可证。贡献章节仅邀请提交 Issue 与 Pull Request。

## 6. 文风与验收标准

- README 以中文为主，技术名词、模块名和命令保留英文；
- 句子简洁，先介绍产品价值，再展示实现细节；
- 不使用营销式夸张表达；
- 所有命令可以从仓库根目录执行；
- 所有相对链接必须指向仓库中真实存在的文件；
- 文档内容与 `settings.gradle.kts`、版本目录和应用构建配置一致。
